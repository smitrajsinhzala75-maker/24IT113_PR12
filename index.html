Q1: What is the difference between Continuous Integration (CI) and Continuous Deployment (CD), and which one does this practical actually demonstrate?

Continuous Integration (CI) is the automated development practice where team members integrate their work into a shared mainline branch (main) multiple times per day. Every commit/push automatically triggers an isolated build, linter check, and automated test suite to verify code health and prevent integration regression. Continuous Deployment (CD) extends this by automatically deploying every validated build directly to production or staging servers without human approval. This practical demonstrates Continuous Integration (CI): it automates dependency installation, code quality linting, and automated API regression testing on every push and pull request targeting main.

Q2: Why does running tests automatically on every push catch problems earlier than testing manually before a release?

1) Immediate Feedback: Developers are alerted within minutes of committing if a specific change broke existing endpoints, while the code logic is fresh in their minds.
2) Small Blast Radius: When a test fails on push, the bug is isolated to the tiny diff of that single commit, rather than debugging months of accumulated changes.
3) Elimination of Human Error: Manual pre-release testing is slow, error-prone, subjective, and prone to skipping edge cases.
4) Clean Environment Parity: CI runs on isolated runners (ubuntu-latest), eliminating "it works on my machine" environmental discrepancies.

Q3: What would happen to the pipeline if the test file path were incorrect — would the workflow fail at the same step as a genuine test failure?

Yes, the workflow would fail at the "Run tests" step, but with a fundamentally different error signature. A genuine test failure occurs when Jest executes the test assertions, encounters a mismatch (e.g. expected HTTP 200, received 500), outputs assertion diffs and stack traces, and exits with code 1. If the test file path or pattern is incorrect, Jest will report "No tests found related to files matching...", or fail during file resolution. Both fail the pipeline, but the logs identify whether it was an assertion logic error vs a configuration/file resolution error.
